# JibunKit 1.0の実装・検証計画

更新日: 2026-09-19。[Issue #5](https://github.com/y-aplus/JibunKit/issues/5)と、その後のユーザー判断を反映。
この文書は1.0へ至る実装・検証計画と当時の到達点を保持する。現在は公開安定版0.8.5/build15、未公開候補1.0.0/build16で、ユーザーが採用範囲の基準充足と公開準備を承認済み。最終公開承認は2026-09-19に取得済みである。P0/P1/P2の採用範囲完了を、親D全体の高度な残件の完了へ拡大しない。
[公開版とmainの状態](../../status.md)、[停止時引継ぎ](../../verification/2026-09-12-development-checkpoint.md)を参照。

## 維持する補完責任

> JibunKitへ統合した結果、独立アプリならOSやアプリ境界によって得られていた隔離・調停・所有権管理が失われるなら、その差分をJibunKitが可能な範囲で補う。

技術的不能と、複雑さ・未要求・サンプル不在・費用による未対応を区別する。
この原則は維持するが、全D項目解消を確定済みの1.0出荷条件として扱う運用はIssue #5で見直す。
**1.0はP0/P1維持、P2-A全体、P2-B通常範囲、採用したP2-Cを必須とする**。この採用範囲は2026-09-19に基準充足と判断された。P3の高度な一般化と未観測条件は後段へ残り、親D全体をcompleteにはしない。0.8.0を1.0達成とは扱わなかった。
[責任と技術判定](../../coexistence-boundaries.md)、[優先度と合格条件](../../implementation-priorities.md)を区別する。

## 既存成果と再利用

親Dの状態・source・比較証拠は[統合差分台帳](../../coexistence-ledger.md)を正本とする。
API/fixtureが存在するだけでは通常Featureでの提供完了にしない。既存成果を再実装せず不足する接続を閉じる。

| まとまり | 既存成果 | 今回の優先対象 |
| --- | --- | --- |
| 独立開発・組込み | Tuist雛形、単独/host、Records、Package resources/翻訳 | P0-4通常追加・更新・誤設定診断は0.7.0で検証済み |
| 保存と寿命 | JSON/ZIP選択復元、stop/apply/resume、SQLite比較、Task/購読/HTTP終了 | P0-Aの通常接続・失敗/取消/移行/診断は非実機条件を検証済み。候補の実機確認も2026-09-13に完了 |
| 画面と利用者操作 | Feature別経路、URL/通知接続、所有者別登録解除API | P0-Bの提示契約・同意・無効化/削除UIは非実機条件を検証済み。候補の実機確認も2026-09-13に完了 |
| OS・外部接続 | 通知/URL/Keychain/Web/HTTP、Package Widget/Intentsの部分検証 | P1-A/BのCIと6beb877/4e6a3f4の対象別実機は確認済み。0.8.0/build10の通常IPA検査も成功し、最終source照合・文書監査も完了 |
| 高度な共存 | background API/共有refresh、SDK alias等の部分検証 | 既存成果を維持。承認済みP2を操作Widget/Controlから進め、P3一般化を別段階へ |

0.6.0後のSDK iOS比較とrefresh診断fixtureも0.7.0候補のソースに含む。refreshの実OS起動は未検証。
backgroundの実OS起動、高度な複数window・任意SDK・外部identity等をP0/P1の出荷前提にしない。
ただしP0/P1で提供すると約束した動作を守るための依存修正は行う。
後段へ送った親Dを完了や技術的不能に変更しない。

## 実行と検証

[大きなCI境界](../../ci-boundaries.md)と[並列運用](../../parallel-implementation.md)に従う。
共通契約と試験を先に固定し、複数単位の実装・通常接続・失敗検証を一括提出/レビューしてからCIを起動する。
各小commitではCIを起動せず、境界内のcheckpointと出荷合格を分離する。
必要な実機確認は成果のまとまりごとに集約し、P2途中は0.8.x公開へつなげる。中間CI成功だけでdevice未確認の単位をcompleteにしない。
minorごとに[公開手順](../../releasing.md)の全現状文書確認と公開後同期を行う。

需要調査はユーザー側ChatGPTの[Issue #6](https://github.com/y-aplus/JibunKit/issues/6)として受領済み。2026-09-15に正式採用した。再調査や新しい調査スレッドをこの計画から自動開始しない。
条件付きのP2-Cは既存成果・残負荷・通常経路の成立から採否を記録し、採用した範囲は検証まで閉じる。署名・外部サービス前提と単なる未実装を区別する。
最初のP0-Aと各minorでCI実数・親のレビュー/メッセージ・検証時間を比較し、分担の効果を見直す。

既存Counter/Reminderの識別子・保存値・通知とバックアップ読込み互換性を維持する。
ignoredのZaiko source/testsは保持し、通常製品へ戻さない。既報のupstream issueを重複作成しない。
旧チェックリストは[履歴資料](../../history/1.0-plan-before-0.6-doc-sync.md)へ保持する。
