## 補完単位（P0/P1の合意範囲を確認済み）

既存成果を再実装せず、plan.jsonに記録した不足と通常利用への接続を閉じる。各合格条件の具体的な操作列・証拠種別も同じ正本に記載する。
P0-3は既存資産を使いJSON/添付とnative SQLiteを最初の対象方式とする。製品にそのDBだけを強制する意味ではない。
P0-5はユーザー回答により**アプリ内UIが0.7.0の必須条件**。無効化・再有効化・登録/所有データ削除を扱い、IPA内のコード除去は再ビルドで行う。

P0の6単位は0.7.0で完了。P1の6単位は通常接続・自動試験に加え、6beb877と4e6a3f4の対象別実機手順を受領済みで、最終sourceの差分照合と現況文書監査を完了した。公開状態は出荷記録を参照する。失敗直後の未取込み行やWidget単純再起動だけの独立観測など、観測していない細部を成功へ補わない。各単位の`existing`、`remaining`、`criteria`は[plan.json](delivery/plan.json)を正本とする。ここへ進捗表を重複掲載せず、公開版/main/開発branchの区分は[status](status.md)、D全体の残件は[台帳](coexistence-ledger.md)を参照する。

## CI境界を先に固定する

| 境界 | 実装する単位 | 合格までに確認する範囲 | 初回CIの上限目安 |
| --- | --- | --- | --- |
| P0-A 寿命・保存・終了診断を通常経路で閉じる | P0-1 / P0-3 / P0-6 | P0-1 / P0-3 / P0-6 | 2 run |
| P0-B 画面提示・同意・無効化削除のアプリ内操作 | P0-2 / P0-5 | P0-1 / P0-2 / P0-3 / P0-5 | 2 run |
| P0-C 追加更新経路とP0全体の0.7.0出荷 | P0-4 | P0-1 / P0-2 / P0-3 / P0-4 / P0-5 / P0-6 | 2 run |
| P1-A 共有入力・Shortcuts・静的WidgetのOS入口 | P1-3 / P1-1 / P1-2 | P0-1 / P0-2 / P0-3 / P0-4 / P0-5 / P0-6 / P1-1 / P1-2 / P1-3 | 3 run |
| P1-B 通知・HTTP・Webの実利用と0.8.0出荷 | P1-4 / P1-5 / P1-6 | P0-1 / P0-2 / P0-3 / P0-4 / P0-5 / P0-6 / P1-1 / P1-2 / P1-3 / P1-4 / P1-5 / P1-6 | 3 run |

各境界はAPI・fixture一つではなく、複数の契約、通常Feature接続、失敗/取消、二ownerの非干渉、利用手順を含む。
P0-Cは単独のP0-4実装に加えてP0全体の出荷確認を扱う。P1-Aでは新規開発量の大きい共有入口を先に設計する。
上限は予算であり空のrunを埋める割当ではない。CI失敗や安全な並列分割が必要なら理由を残して増やす。
一境界を複数run/jobへ分けた場合は実数を記録し、「1バッチ」と呼んで消費を隠さない。
チェックポイントcommit/pushとCI境界を分離し、各小変更・子の提出ごとにCIを走らせない。
途中のCI境界では実機専用条件を対応minorの候補へ予約できるが、その単位をcompleteにはしない。P0-C/P1-Bの出荷判断までに閉じる。
詳細は[大きなCI単位の運用](ci-boundaries.md)。

P2の事前境界はP2-W（操作Widget/Control）、P2-L（継続表示）、P2-C（撮影/音声）、P2-B（背景/位置）、P2-I（外部identity/Push）、P2-S（BLE/通常scene）、P2-F（条件付き採否/採用範囲と全体出荷）。最初の二境界は各2run、後続は各3runを初回予算とし、APIごとや担当ごとに実行しない。詳細な入力/filterと所要時間は投入前に固定する。

旧追跡ID P2-1〜7の意味を保持する。旧Issue #5のP3領域からBLE/通常位置監視/通常window/外部identity/APNsを上記P2へ切り出す。これは親D全体の完了や高度構成の採用を意味しない。機械可読の追加ID・条件・CI境界はplan.jsonで管理する。

同じOS・署名条件の独立アプリで得られる境界との差分を補う。無料署名/SideStore、有料登録、entitlement、外部server・機器の条件を分け、根拠のない「SideStoreでは不能」で省略しない。利用可能な構成の通常経路を確認し、補完不能ならAPI/署名条件・再現結果と可能な緩和を記す。条件付きで使える範囲と未実装を同一視しない。

### 後段に残すP3

任意SDKの互換性のない複数version/C・ObjC・binary/globalの一般隔離、任意extension/宣言の万能合成、任意View/実行instanceの自動管理、特殊認証/全Web形式/活動連携、特殊機器・高度な同時capture・監視枠の透過仮想化、大量要求最適化、高度AR world state、helperによる強制障害隔離を残す。

対象から外すときは追加構成を具体化し、P2の通常主機能を損なわない理由を説明する。提供範囲の通常中断・復帰・背景再接続・所有者分離の不具合をP3へ分類変更して出荷しない。実Featureで遭遇する具体的なSDK/OS/provider問題は繰上げ候補とする。

### 実装と出荷の順序

操作Widget/Control → 継続表示 → 撮影/音声 → 背景実行/位置 → 外部identity/BLE/APNs/通常window → P2-C採否と採用範囲を基本順とする。独立した実装は並行してよい。小修正や担当提出ごとにCIを回さず、通常入口・二owner・取消/失敗・管理・OS証拠・ガイドまでを事前境界に含める。

P2途中の実機確認済みのまとまりは0.8.xで公開する。1.0は全必須範囲と採用した条件付き範囲、P0/P1回帰、必要な実機、全文書・互換性・配布物の検査が揃ってから公開判断する。今回の境界採用は1.0公開そのものの承認ではない。

## 状態と証拠

優先度、実装状態、出荷対象は別軸。P0/P1の単位が完了しても親Dを一括完了にしない。
plan.jsonのpartialは実装・通常接続・必要検証・手順のいずれかが残る状態。実装済みで実機結果だけを待つ単位も含む。completeへ変更するには合格条件ごとの証拠とレビューが必要。
標準API・unit・Simulator・実機の証拠を分離し、対象source、操作、観測、残件を記録する。
P0はCI34705653297と2026-09-13の一括実機で確認し0.7.0、P1は0.8.0で公開済み。公開安定版は0.8.4/build14。背景・位置・BLE・window/AR等の中間成果は[0.8.4記録](verification/2026-09-18-0.8.4-release.md)を参照。以下の撮影/音声出荷は0.8.3時点の証拠。撮影/音声の採用通常範囲を対象別CI・実機で確認し、版変更後のbuild/公開を完了した。需要調査Issue #6は2026-09-13に受領し、1.0の正式境界は0.8.0公開後の2026-09-15に確定した。[出荷照合](verification/2026-09-17-0.8.3-release.md)。
