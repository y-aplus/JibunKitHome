# 摩擦ログの仕分け（upstreamへの提案候補の選定）

Zaikoのセルフベータで出た摩擦（`friction-log.md` の F-001〜F-009）を、
「一般ユーザーに効くか、メンテナー固有か」で仕分けたもの。

判定の軸:

- **影響を受ける人**: 全ユーザー / 派生host作成者 / Feature作者 / メンテナー固有 / 自分の環境固有
- **修正の所在**: upstream文書 / upstreamコード / 派生側の手順 / ローカル環境
- **提案優先度**: 高（同じ所で一般ユーザーも詰まる）/ 中（時間は使うが回避できる）/ 低（気付きにくい）/ 提案しない

## 一覧

| ID | 要約 | 影響を受ける人 | 修正の所在 | 優先度 |
| --- | --- | --- | --- | --- |
| F-001 | 派生リポジトリの作り方そのものが文書に無い | 派生host作成者（全員が最初に踏む） | upstream文書 | 高 |
| F-002 | bundle ID / App Group を維持するかの判断が間接的 | 派生host作成者 | upstream文書 | 高 |
| F-003 | 公開基盤のworkflowが派生側で動くか | 派生host作成者 | upstream文書（実測結果の追記） | 中 |
| F-004 | `Modules/` と root `Sources/` の使い分け基準が薄い | Feature作者 | upstream文書 | 高 |
| F-005 | 派生側の私的文書置き場が決まっていない | 派生host作成者 | upstream文書 | 低 |
| F-006 | iOS型検査のローカル手段が文書化されていない | 実質メンテナー／自分の環境 | ローカル手順 | 低（F-008へ統合） |
| F-007 | ルートの `swift test` がLinuxで通らない（文書と不一致） | 全ユーザー（非mac環境） | upstreamコードまたは文書 | 高 |
| F-008 | 非macOSでローカルにできることの一覧が無い／Linux版Tuistは生成できない | 全ユーザー（非mac環境） | upstream文書 | 中 |
| F-009 | ghの既定リポジトリ未設定で、upstream側にrunが作られうる | 実害=メンテナー固有／摩擦=全ユーザー | upstream文書（1行） | 中 |

## 判定の理由（要点）

- **F-001 / F-002 / F-004**: いずれも「最初の一歩」または「最初の設計判断」。文書化されていないので、利用者は自分で決めるか詰まる。派生モデルを使う人は必ず通る。→ 一般ユーザーに効く。優先度 高。
- **F-007**: `docs/build.md` の「Linux／WSLでも `swift test` でFoundationロジックを確認できる」は現状のmainで成立しない（CoreがCryptoKit等でLinuxビルド不能）。文書どおり試した人が必ず失敗する。→ 一般ユーザーに効く。優先度 高。副作用として「Featureを `Modules/` に置く」判断の根拠にもなる（F-004と関連）。
- **F-003**: 既定入力は派生側で成功したため、実質は「残りの入力群が未確認」。→ 中（追記すれば閉じる）。
- **F-008 / F-006**: 非macOS利用者の計画と所要時間に効く。F-006は「廃止済みのxtool経路で入れたDarwin SDKがWSLに残っている人」の環境依存なので、一般ユーザーには再現しない。一般化できるのは「ローカルでできることの一覧」＝F-008の方。→ F-008に統合して中、F-006単体は低。
- **F-009**: `workflow_dispatch` は対象リポジトリへのwrite権限が必要なため、**実害（基盤リポジトリでrunが走る）はメンテナー固有**。一般ユーザーは `Not Found` で止まるだけで、残るのは「対象が曖昧なまま失敗し、原因がどこにも書かれていない」という摩擦。→ 混在。修正は1行なので、一般ユーザーにも効く。優先度 中。
- **F-005**: 置き場所を自分で決めれば回避できる。→ 低。

## 結論

- **upstream提案の候補（優先度高）**: F-001、F-002、F-004、F-007
- **中**: F-003（実測の追記）、F-008（F-006を統合）、F-009（`gh repo set-default` の1行）
- **低／提案しない**: F-005、F-006単体
- **派生側で先に閉じるもの（実施済み）**: F-009の手順（`gh repo set-default y-aplus/JibunKitHome` を実行済み）、F-005（`docs-local/` の存在をこの作業で確立）

提案そのものは upstream に送らない（この派生hostは upstream へ何も入れない方針）。材料としてここに置く。
